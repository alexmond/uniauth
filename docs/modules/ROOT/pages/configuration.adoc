= Configuration
:description: Every uniauth.* property, and the Boot properties UniAuth reads rather than replaces.

== Top level

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.enabled` | `false` | *Must be set to `true`.* The starter installs nothing unless asked — see below.
| `uniauth.login-page` | `/login` | The chooser page.
| `uniauth.default-success-url` | `/` | Where a successful sign-in lands.
| `uniauth.logout-success-url` | `/login?logout` | Where a sign-out lands.
| `uniauth.providers-endpoint` | `/uniauth/providers` | JSON list of enabled providers.
| `uniauth.public-paths` | _empty_ | Routes reachable without a session.
|===

The starter already permits its login page, the providers endpoint, `/error` and the pending
page; `public-paths` is for your own routes.

[IMPORTANT]
====
`uniauth.enabled` defaults to *false*. This library decides who may reach what, so being on
the classpath is not consent: adding the dependency used to install a catch-all chain in
every profile and every test, overriding an application's own rules before a line of
integration was written. The symptom was a broadly-locked application rather than an
obviously broken one.

When it does install, it says so once at INFO, naming the default rule and the permitted
paths, so an application whose rules stopped applying can find out why from its startup log:

[source]
----
UniAuth installed a SecurityFilterChain: every request needs authentication and approval,
except [/, /how-it-works, /css/**] which are permitted. Providers: [internal, ldap, google].
Set uniauth.enabled=false to back off entirely.
----
====

[#switching-uniauth-off]
=== Switching UniAuth off is not the same as no security

`uniauth.enabled=false` backs *this starter* off entirely. It does not leave the
application open, and the surprise is a login page nobody configured.

With the starter on the classpath, `spring-boot-starter-security` is too — and Spring Boot's
own security auto-configuration takes over, which locks every path behind a generated
password printed once at startup:

----
Using generated security password: 8e8f2f0c-...
----

That is Boot being helpful, not UniAuth leaving something behind, and it is the right
default for an application that simply has no security configured yet. It is not what
somebody expects who switched UniAuth off to run an application open on a trusted network
during development (#33).

An application that wants none says so itself:

[source,java]
----
@Bean
@Profile("dev")
SecurityFilterChain open(HttpSecurity http) throws Exception {
    return http.authorizeHttpRequests((rules) -> rules.anyRequest().permitAll())
        .csrf(AbstractHttpConfigurer::disable)
        .build();
}
----

Declaring any `SecurityFilterChain` of your own also backs Boot's default chain off, so this
is the whole of it. The starter's own catch-all backs off on its bean *name*, so this does
not have to be an either/or: a chain of your own can sit beside UniAuth's when you want
both.

WARNING: `permitAll()` means what it says. Scope it to a profile, as above, rather than
leaving it in the configuration an application deploys with.

== Internal store

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.internal.enabled` | `false` |
| `uniauth.internal.display-name` | `Username & password` | Label on the chooser.
| `uniauth.internal.users[].username` | | 
| `uniauth.internal.users[].password` | | Encoded, with a `{noop}` or `{bcrypt}` prefix.
| `uniauth.internal.users[].roles` | `[USER]` | Without the `ROLE_` prefix.
|===

[#bringing-your-own-accounts]
=== Bringing your own accounts

You do not have to declare accounts under `uniauth.internal.users` to get a password form.
An application that registers an `AuthenticationProvider` bean of its own gets one, and
UniAuth puts that provider on the same chain — which is how a local break-glass account
sits beside Google on one login page.

This did not use to work. The form was offered on the strength of
`uniauth.internal.enabled` and `uniauth.ldap.enabled` alone, so an application holding its
credentials elsewhere got a page with the redirect buttons and nothing to type into — and
because the same answer installs the form-login filter, there was nothing listening on the
login path either. Declaring the accounts a second time under `uniauth.internal.users` was
the only way through, which means keeping them in two places (#9).

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.form.enabled` | _unset_ | Offer the shared password form, or suppress it. Left
unset it is worked out: on when a form mechanism is enabled, or when the application
registered an `AuthenticationProvider` of its own.
|===

Set it when your accounts are not reachable that way — an `AuthenticationManager`, or a bare
`UserDetailsService`.

[IMPORTANT]
====
A `UserDetailsService` alone is deliberately *not* read, and that is a security boundary
rather than an omission. Spring Boot's own fallback account — `user`, with a password
generated at startup and printed to the log — is contributed as exactly that type, and it
can sign in through this chain once a form-login filter exists. Reading the type would mean
an application that installed no mechanism at all getting a password form that admits it,
turning a visibly broken configuration into a quietly reachable one.

If your accounts are only a `UserDetailsService`, say so in one line — either
`uniauth.form.enabled: true`, or `uniauth.internal.enabled: true`, which has the same
effect by a different route: the internal store's own user-details bean backs off on
`@ConditionalOnMissingBean`, so UniAuth's provider is built around your accounts rather
than around an empty list.
====

WARNING: `uniauth.form.enabled: false` suppresses the form *and the filter behind it*,
because the two have always been one answer. Internal and LDAP accounts then have no way
in; it is for a chain meant to offer redirect providers only.

== LDAP

NOTE: Needs `spring-boot-starter-ldap` and `spring-security-ldap` on the classpath — they are
optional dependencies of the starter. See xref:getting-started.adoc#_adding_a_directory[Adding
a directory] for why.

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.ldap.enabled` | `false` |
| `uniauth.ldap.display-name` | `Directory account` | Label on the chooser.
| `uniauth.ldap.url` | | Server *and* base DN, e.g. `ldap://host:389/dc=example,dc=com`.
| `uniauth.ldap.user-dn-patterns` | `[uid={0},ou=people]` | Relative to the base DN.
| `uniauth.ldap.group-search-base` | `ou=groups` |
| `uniauth.ldap.group-search-filter` | `(member={0})` |
| `uniauth.ldap.manager-dn` | | Bind account for the group search.
| `uniauth.ldap.manager-password` | |
|===

The context source is qualified as `uniAuthLdapContextSource` rather than resolved by type,
because Boot's own `LdapAutoConfiguration` publishes a `BaseLdapPathContextSource` bound to
`spring.ldap.*`. Without the qualifier a plain `@ConditionalOnMissingBean` would back off and
silently ignore `uniauth.ldap.url`.

== OAuth2 / OIDC

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.oauth2.enabled` | `true` | Registrations still have to exist.
| `uniauth.oauth2.github.fetch-email` | `false` | Second call for an address GitHub will not volunteer.
| `uniauth.oauth2.github.emails-uri` | `https://api.github.com/user/emails` |
| `uniauth.oauth2.microsoft.multi-tenant` | `false` | Tenant-template issuer validation.
|===

Registrations themselves come from Boot:
`spring.security.oauth2.client.registration.*` and `.provider.*`.

== SAML 2.0

NOTE: Needs `spring-boot-starter-security-saml2` on the classpath — an optional dependency of
the starter, and the one that also obliges a build to declare the Shibboleth repository. See
xref:getting-started.adoc#saml-repository[Adding SAML 2.0] for why it is not transitive.

[cols="2,1,3"]
|===
| Property | Default | What it does
| `uniauth.saml.enabled` | `true` | Registrations still have to exist.
|===

Registrations come from `spring.security.saml2.relyingparty.registration.*`.

== Approval gate

[cols="2,1,3"]
|===
| Property | Default | What it does

| `uniauth.approval.enabled` | `false` |
| `uniauth.approval.require-for` | `[OAUTH2, SAML, LDAP]` | Which mechanisms are held. Internal accounts are excluded by default: writing one into configuration is already an approval.
| `uniauth.approval.pending-page` | `/pending` | Where a held principal waits.
| `uniauth.approval.default-roles` | `[USER]` | Granted when an approver approves without naming roles. A federated principal has none of its own.
| `uniauth.approval.invitations.enabled` | `false` | Admitting a named person before their first login. Needs `uniauth.approval.enabled`.
| `uniauth.approval.invitations.path` | `/invite/{token}` | Where an invitation is redeemed. Must contain `{token}`; validated at startup. Permitted on the chain, since it has to work before anybody has logged in.
| `uniauth.approval.invitations.default-expiry` | `14d` | How long an invitation lasts when its creator names no ttl.
| `uniauth.approval.invitations.invite-only` | `false` | Refuse an uninvited principal outright — a plain 403 rather than the waiting page.
|===

implementation is not production-fit.

== A property trap worth knowing

Binding a *list* entry from an environment variable replaces the whole collection rather than
merging into it, because the higher-priority source wins outright. Supplying only

----
UNIAUTH_INTERNAL_USERS_0_PASSWORD=…
----

therefore blanks that entry's username and roles. When any field of a list entry comes from
the environment, supply all of them.
