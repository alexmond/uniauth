A *Spring Boot starter* that puts an internal user store, OAuth2/OpenID Connect, SAML 2.0 and LDAP
behind a *single* `SecurityFilterChain`, with a login page that lets the user pick whichever
mechanisms are switched on.

== Why UniAuth

* *Four mechanisms, one chain.* Chains match in order and the first match wins, so one chain per
  mechanism would mean only the first ever runs. Adding a second way in does not mean a second chain.
* *No re-declared OAuth2 or SAML configuration.* Registrations come from Spring Boot's own
  `spring.security.oauth2.client.registration.*` and `spring.security.saml2.relyingparty.*` — two
  lines of standard config add Google, and the chooser, brand and OIDC detection follow from it.
* *Local accounts beside a directory.* Form-based mechanisms share one form and are told apart by the
  `AuthenticationProvider` chain, so break-glass accounts survive a directory outage.
* *An optional approval gate.* Authenticating and being admitted are separate decisions — a provider
  will vouch for anyone holding an account with it, which is not the same as letting them in.
* *Provider quirks as opt-in adapters, never new mechanisms* — GitHub's second call for an email
  address, Microsoft's multi-tenant issuer.

== Get started

[source,xml,subs="attributes+"]
----
<dependency>
    <groupId>org.alexmond</groupId>
    <artifactId>uniauth-spring-boot-starter</artifactId>
    <version>{uniauth-version}</version>
</dependency>
----

Nothing is enabled by default beyond the chain itself, so switch on at least one mechanism:

[source,yaml]
----
uniauth:
  internal:
    enabled: true
    users:
      - username: alice
        password: "{noop}s3cret"     # use {bcrypt}… anywhere real
        roles: [ USER, ADMIN ]
----

Everything but the login page now needs a session. Adding a directory, an OIDC provider or the
approval gate is a few more lines each — see the
https://www.alexmond.org/uniauth/current/getting-started.html[getting started guide].

NOTE: Enabling SAML pulls in OpenSAML, which is *not published to Maven Central*. That build needs
the https://build.shibboleth.net/maven/releases/[Shibboleth repository], or it fails to resolve
`org.opensaml:*`.

== Examples

The repository ships a demo stack under `uniauth-examples/`, plus the two services that keep it
honest — an OAuth2/OIDC provider and an admin console, each its own process.

[source,bash]
----
./mvnw -Pdefault -DskipTests install                          # the -pl below resolves from the repo
./mvnw -Pdefault -pl uniauth-examples/webapp spring-boot:run  # http://localhost:8080
----

|===
| Module | What it is

| `uniauth-examples/webapp` | Server-rendered demo: chooser, public and protected pages, approval queue.
| `uniauth-examples/headless` | API-first — answers `401` instead of redirecting.
| `uniauth-authserver` | An OAuth2/OIDC provider, its own service. Deliberately does not depend on the starter.
| `uniauth-admin` | A standalone console that administers the provider and the directory.
|===

Only `uniauth-spring-boot-starter` is published to Maven Central; the rest are demonstrations.
